MCP Server

PMP ships with a built-in MCP (Model Context Protocol) server that exposes your projects and tasks to AI assistants and other MCP-compatible tools.

It runs locally over stdio, so an MCP client launches pmp as a subprocess and talks to it over standard input/output. Your data never leaves your machine.

Start the server

Section titled “Start the server”

The server starts and prints [pmp] MCP server listening on stdio, then waits for MCP requests. It’s not meant to be run interactively; launch it through an MCP client instead.

What it exposes

Section titled “What it exposes”

Tools

Section titled “Tools”

The server exposes tools to manage projects, versions, tasks, dependencies and notes:

Domain Tools
Projects list_projects, create_project, update_project
Versions list_versions, create_version, update_version
Tasks list_tasks, create_task, update_task, update_task_status, update_task_priority
Dependencies get_task_dependencies, get_task_dependents, add_task_dependency, set_task_dependencies, remove_task_dependency
Notes list_task_notes, add_task_note, delete_task_note

Tasks are created with context, requirements and benefits, start as todo and accept a priority (Low, Medium, High, defaulting to Medium).

Tip

Marking a task done fails with a validation error while it still has incomplete dependencies. Check a task’s blockers with get_task_dependencies before closing it.

Resources

Section titled “Resources”

The server also exposes read-only resources for browsing data:

URI Description
pmp://projects All projects
pmp://projects/{id} A single project
pmp://projects/{id}/tasks Tasks of a project
pmp://projects/{id}/versions Versions of a project
pmp://versions/{id}/tasks Tasks of a specific version
