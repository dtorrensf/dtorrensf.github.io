TUI Guide

PMP’s terminal interface (TUI) is a keyboard-driven way to manage your projects and tasks. Launch it with:

Every screen shows its available shortcuts in a footer at the bottom, so you can always discover what a key does. Press ? for the full list, grouped by topic; ? or Esc closes it. On forms where you type text, ? is entered as a character instead.

Messages such as successful saves or errors appear as short notices just above the footer. Success messages disappear after three seconds; errors stay until you press Esc.

Navigation basics

Section titled “Navigation basics”
Keys Action
↑ / ↓ or j / k Move the selection
Enter Open / edit the selected item
Esc Go back
q Quit
? Show every shortcut of the current screen
Ctrl+C Force quit

Project list

Section titled “Project list”

On startup you land on your list of projects. From here you can:

Key Action
Enter Open the selected project
c Create a new project
e Edit the selected project
d Delete (with confirmation)
r Refresh the list
q Quit

Project dashboard

Section titled “Project dashboard”

Opening a project shows an overview with:

  • The project description (scroll with PageUp / PageDown).
  • A Status block with one row per status (Todo, In Progress and Done), each with a bar, its task count and its share of the project.
  • A Progress gauge showing done/total tasks and the completion percentage. When the terminal is wide enough, a 14 days sparkline sits beside it with the number of tasks completed each day over the last two weeks (UTC days).
  • A Versions list, each with its own stacked progress bar and per-status counts.
Key Action
Enter Open the selected version
c Create a new version
v Edit the selected version
r Cycle version status (Backlog → Open → Released)
e Edit the project
d Delete (with confirmation)
Esc Back to the project list
q Quit

v edits the selected version itself (name, description and status), while c creates a new version and e edits the project. In the version form, Tab moves between fields, ← / → or Space changes the status and Ctrl+S saves.

Managing tasks

Section titled “Managing tasks”

Open a version to see its task list. The header shows Project · Version · Status, plus · N summaries when the version is Released or already has a summary.

Key Action
Enter Edit the selected task
Tab Cycle the task status (Todo → In Progress → Done)
c New task
d Delete (with confirmation)
f Filter the list by name, status or priority
x Clear all filters
o Change the sort order (see below)
m Move the selected task to another version
s Open the latest summary
e Export the latest summary to Markdown
r Refresh the list
Esc Back to the project dashboard
q Quit

Moving a task to another version

Section titled “Moving a task to another version”

m opens the Move task to version popup with the other versions of the same project. Use ↑ / ↓ or j / k to choose one, Enter to move the task and Esc to cancel. When the project has no other version, the popup says This is the only version of the project.

Moving only changes the version: notes, status, priority and dates stay with the task. The move fails while the task has dependencies or dependents, because they must stay within one version. Clear them from the task form first.

Reviewing summaries

Section titled “Reviewing summaries”

Press s to open the latest summary of the version. The prose scrolls with j / k and Esc returns to the task list; a Distribution block at the bottom counts tasks by status and priority.

Press e to export the same summary to Markdown. PMP writes the file to the exports folder and shows Exported to <path>.

Both keys only act when the version already has a summary. See Version Compaction for the full workflow.

Filtering tasks

Section titled “Filtering tasks”

f opens the Filter Tasks popup with three fields:

Field Action
Title Type part of a name; the match is case-insensitive
Status ← / → choose Todo, In Progress or Done (Any until you pick)
Priority ← / → choose Low, Medium or High (Any until you pick)

Use Tab to move between fields, Backspace to edit the title, Enter to apply the filters and Esc to close the popup without changing them. The task list title then shows the active filters, for example Tasks (Title: api - Status: Todo), or just Tasks when none are active.

Press x in the task list to clear every filter at once.

Sorting tasks

Section titled “Sorting tasks”

o cycles the order of the task list:

  1. Priority (default): tasks that are not done come first, then higher priorities, then the newest tasks.
  2. ID ascending: tasks in creation order.
  3. ID descending: newest tasks first.

The selection stays on the same task when the order changes.

Editing a task

Section titled “Editing a task”

The task form has these fields, in tab order: name, description, status, priority, dependencies and notes.

Key Action
Tab Move to the next field
← / → or h / l Change the status or priority
Enter (Description) Insert a new line
Enter (Dependencies) Open the dependency picker
Enter (Notes) Add the typed note (existing tasks)
PageUp / PageDown Scroll the dependency or notes list
Ctrl+S Save
Esc Cancel and go back

The description is a full multiline editor: Enter adds a line and the arrow keys, Home, End, Backspace and Delete work as expected.

The dependency picker (opened with Enter) lists the other tasks of the version. Type to filter by name, use ↑ / ↓ or j / k to move, Space to check or uncheck a task and Enter to close the picker keeping the selection. Esc reverts the changes made since the picker was opened.

In the notes field, type the note in New note and press Enter to add it to the task. Existing notes are listed with their date above the input. Notes can be added once the task has been saved for the first time.

Statuses and priorities

Section titled “Statuses and priorities”

Tasks have one of three statuses:

Status Meaning
Todo Not started yet
In Progress Being worked on
Done Completed

And one of three priorities: Low, Medium or High.

Task dependencies

Section titled “Task dependencies”

A task can depend on other tasks. PMP prevents you from marking a task as Done while its dependencies are still incomplete, so you never close a task out of order.

Dependencies are managed from the task form: focus the Dependencies field, press Enter and use the picker to select the tasks this one depends on.

Deleting items

Section titled “Deleting items”

Projects, versions and tasks are deleted with d after a confirmation dialog. Only lowercase y confirms; any other key cancels.

Item Confirmation message
Project Delete project <name>? This will remove all its tasks ⚠️. (y/N)
Version Delete version <name>? Its tasks will be removed. (y/N)
Task Delete task <name>? (y/N)

When a task blocks other tasks, its dialog warns that the dependency links will be removed too: Deleting will remove <n> dependency links. Continue? (y/N).

Versions

Section titled “Versions”

Versions group a project’s tasks into milestones (for example v0.2.0). Each version tracks its own progress and can be Backlog, Open or Released. New versions start in Backlog, which is where planned work waits before a release line is opened. Cycle the status with r on the project dashboard or change it in the version form.

Tasks and their dependencies stay within their version, so you can follow the progress of each milestone independently.

Once a version is finished, PMP can freeze its Done tasks into a summary. From the version dashboard, s opens the latest summary and e exports it as Markdown. Both keys are available only when the version already has a summary. See Version Compaction.
